# الباك إند — لوحة تحكم الأدمن لـ سفر المزامير

هذا الباك إند **إضافة اختيارية** فوق الموقع الستاتيك الأصلى. الموقع بالكامل (`index.html`, `psalm.html`, إلخ)
لسه شغّال حتى بدون الباك إند ده — الباك إند بس بيضيف لوحة تحكم أدمن (`admin.html`) بتقدر منها
تعدّل نصوص المزامير، ترفع صوت، وتتحكم فى رسالة إعلان على الموقع، مع **سجل تعديلات شفاف** لأى تصحيح.

## المعمارية باختصار

- **بدون حسابات زوار** — بيانات الزوار العادية (المفضلة، الحفظ، التقدم) لسه محلية على جهاز كل زائر
  زى ما كانت بالظبط (`localStorage` + `IndexedDB`)، مفيش أى تغيير هنا.
- **أدمن واحد بس** بيسجّل دخول من `admin.html`.
- **قاعدة بيانات = ملفات JSON عادية** (مش Postgres أو أى قاعدة بيانات منفصلة) — أبسط وأرخص فى النشر،
  ومناسبة تمامًا لحجم المشروع ده (أدمن واحد، ١٥١ مزمور).
- السيرفر (`server.js`) بيقدّم نفس ملفات الموقع الستاتيكية + بيضيف API فوقها. رابط
  `data/psalms.json` اللى الموقع بيقرأ منه بقى **ديناميكى** — بيرجّع نفس البيانات، بس دلوقتى
  قابلة للتعديل من لوحة التحكم بدل التعديل اليدوى.

## الملفات المضافة

```
server/
├── package.json
├── .env.example        ← انسخه إلى .env واملأه
├── server.js            ← نقطة التشغيل الرئيسية
├── db.js                 ← طبقة البيانات (قراءة/كتابة ملفات JSON بأمان)
├── auth.js                ← تشفير كلمات المرور (bcrypt) والتحقق من الدخول
├── middleware/requireAdmin.js
├── routes/ (auth, psalms, audio, settings, stats)
├── scripts/create-admin.js  ← لإنشاء أول حساب أدمن
└── data/                 ← يُنشأ تلقائيًا: admins.json, settings.json, edit-log.json, sessions/

admin.html                ← لوحة التحكم (فى جذر المشروع، بجانب باقى الصفحات)
css/admin.css
js/admin.js
```

## التشغيل محليًا

```bash
cd server
cp .env.example .env
# افتح .env وغيّر SESSION_SECRET و ADMIN_USERNAME و ADMIN_PASSWORD

npm install
npm run create-admin   # يُنشئ حساب الأدمن مرة واحدة من قيم .env

npm start               # يشغّل السيرفر على http://localhost:3000
```

بعدها:
- الموقع العادى: `http://localhost:3000`
- لوحة التحكم: `http://localhost:3000/admin.html`

بعد إنشاء الأدمن، يُفضَّل حذف `ADMIN_PASSWORD` من `.env` (الحساب اتخزّن مُشفَّرًا بالفعل فى
`server/data/admins.json`، مش محتاج القيمة التانية).

## ماذا يستطيع الأدمن أن يفعل؟

| الصفحة | الوظيفة |
|---|---|
| نظرة عامة | إحصاءات المحتوى (عدد المزامير، الآيات، كام مزمور له صوت) |
| المزامير والنصوص | تعديل العنوان/المقدمة، وتعديل نص أى آية — كل تعديل بيتسجّل تلقائيًا مع النص القديم والجديد |
| الصوت | رفع ملف mp3 لأى مزمور (بيستبدل القديم)، أو حذفه |
| إعدادات الموقع | رسالة إعلان تظهر فى الصفحة الرئيسية، ووضع صيانة (علم متاح للاستخدام لاحقًا) |
| سجل التعديلات | كل تعديل حصل، امتى، وبواسطة مين |

## الأمان — أهم النقاط

- كلمات المرور مُشفَّرة بـ bcrypt (لا تُخزَّن أبدًا كنص صريح).
- **رؤوس أمان كاملة (Helmet + CSP)**: سياسة أمان محتوى (Content-Security-Policy) تمنع تحميل أى
  سكريبت أو ستايل من مصدر غير موثوق، ومنع تضمين لوحة الأدمن فى أى iframe خارجى (حماية من
  Clickjacking)، بالإضافة إلى `Strict-Transport-Security` و`X-Content-Type-Options`.
- **تحديد معدل الطلبات على طبقتين**: حد عام لكل الـ API (٣٠٠ طلب/١٥ دقيقة لكل IP)، وحد أشد على
  تسجيل الدخول وتغيير كلمة المرور تحديدًا (١٠ محاولات/١٥ دقيقة) ضد هجمات التخمين.
- محاولات الدخول محدودة (Rate Limit) — ضد الاختراق بالتخمين.
- الجلسات (Sessions) محفوظة كملفات على السيرفر نفسه (`session-file-store`)، مش فى الذاكرة —
  تفضل شغّالة حتى لو السيرفر أعاد التشغيل.
- كل مسارات التعديل (`PATCH`/`POST`/`DELETE`) محمية بـ `requireAdmin` — تتطلب جلسة دخول صالحة.
- الكوكيز `httpOnly`، و`sameSite: strict` (حماية من CSRF)، و`secure` فى بيئة الإنتاج (production).
- **فحص أمان عند إقلاع السيرفر**: يرفض التشغيل فى وضع الإنتاج لو `SESSION_SECRET` لسه القيمة
  الافتراضية أو قصير جدًا — بدل ما ينشر بغلطة أمنية بصمت.
- **تحقق من صحة المدخلات (Validation)**: أرقام المزامير/الآيات، وحد أقصى لطول العنوان
  (٢٠٠ حرف) والمقدمة (٢٠٠٠ حرف) ونص الآية (٣٠٠٠ حرف) — ضد إدخال بيانات ضخمة أو مشوّهة.
- **معالج أخطاء عام (Global Error Handler)**: أى خطأ غير متوقع فى أى مسار بيترجم لرد JSON
  واضح، بدون تسريب تفاصيل تقنية داخلية (Stack Trace) للمستخدم فى بيئة الإنتاج.
- **حماية من انهيار العملية بالكامل**: أخطاء غير متوقعة (uncaught exceptions) بتتسجّل فى
  الـ log بدل ما توقف السيرفر بصمت.
- **إغلاق آمن (Graceful Shutdown)**: عند إعادة النشر على Render/Railway، السيرفر بيقفل
  الاتصالات بأمان بدل ما يقطعها فجأة.
- **تغيير كلمة المرور** متاح من داخل لوحة التحكم مباشرة (تبويب الإعدادات) — مش محتاج ترمينال.

كل نقطة من دول اتفحصت فعليًا بتشغيل حقيقى للسيرفر (٢١ اختبارًا تلقائيًا يغطى تسجيل الدخول
الصحيح والخاطئ، الحماية من التعديل بدون تسجيل دخول، صحة المدخلات، تغيير كلمة المرور، وسجل
التدقيق) — مش مجرد مراجعة كود.

**ما لم يُنفَّذ بعد (نقاط تحسين مستقبلية إن كبر المشروع):**
- استعادة كلمة مرور منسية بدون وصول للترمينال (حاليًا لازم `create-admin` تانى أو الاتصال المباشر بالسيرفر).
- تدقيق (Content-Security-Policy) أشد صرامة لاحقًا يمنع `unsafe-inline` تمامًا (يحتاج إعادة هيكلة
  السكريبتات المضمّنة فى بعض الصفحات — تحسين تدريجى وليس ضروريًا الآن).
- نسخ احتياطى تلقائى — راجع قسم "النسخ الاحتياطى" تحت.

## النشر — الخيار الموصى به: Render.com

اخترت Render لأنه بسيط (نشر مباشر من GitHub)، وفيه قرص دائم (Persistent Disk) رخيص محتاجه
عشان ملفات JSON والصوت المرفوع تفضل موجودة بعد كل تحديث.

### الخطوات

1. **ادفع المشروع لمستودع GitHub** (لو لسه مش موجود هناك).

2. **من لوحة Render** (render.com):
   - New → Web Service → اختر المستودع
   - **Root Directory**: اتركه فارغًا (جذر المشروع، مش `server/`)
   - **Build Command**: `npm install --prefix server`
   - **Start Command**: `node server/server.js`
   - **Instance Type**: Starter (أرخص خطة بتدعم قرص دائم — تقريبًا $7/شهر)

3. **أضف قرص دائم (Persistent Disk)** من إعدادات الخدمة:
   - Mount Path: `/opt/render/project/src/server/data` (لحفظ بيانات الأدمن وسجل التعديلات)
   - أضف قرص ثانٍ (أو نفس القرص بمسار أعمق) لـ `/opt/render/project/src/audio` (ملفات الصوت المرفوعة)
   - **مهم**: بدون قرص دائم، أى تعديل أو صوت مرفوع هيتمسح مع كل نشر جديد (deploy).

4. **متغيرات البيئة (Environment)** فى نفس صفحة الخدمة:
   ```
   NODE_ENV=production
   SESSION_SECRET=<نص عشوائى طويل وفريد>
   PORT=10000   (Render بيحدده تلقائيًا غالبًا، تأكد من التطابق)
   ```

5. **إنشاء الأدمن أول مرة** بعد نجاح النشر: من تبويب "Shell" فى Render:
   ```bash
   cd server
   ADMIN_USERNAME=admin ADMIN_PASSWORD=كلمة-مرور-قوية node scripts/create-admin.js
   ```

6. افتح `https://your-app.onrender.com/admin.html` وسجّل الدخول.

### بديل: Railway.app

نفس الفكرة تقريبًا (نشر من GitHub، قرص دائم/Volume بحوالى $5/شهر usage-based) — خطوات الإعداد
شبه Render، الفرق بس فى واجهة لوحة التحكم.

## النسخ الاحتياطى

كل بيانات الأدمن والمحتوى فى ملفات JSON عادية:
- `data/psalms.json` (نصوص المزامير)
- `server/data/admins.json`, `settings.json`, `edit-log.json`
- `audio/*.mp3`

انسخهم دوريًا (يدويًا، أو بسكريبت بسيط `cron` على السيرفر يعمل `tar` ويحطه فى تخزين خارجى).
ده أبسط بكثير من نسخ احتياطى لقاعدة بيانات حقيقية، وميزة إضافية لاختيار "ملفات JSON" بدل DB.
